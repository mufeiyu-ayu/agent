# PR Review 评论处理

读取 [交付流程](../../../docs/workflow.md) 与当前工具适配文件；本 Skill 不是 Issue 交付的默认步骤。用户要求只解释或只修指定项时按该范围执行。

1. 用已认证 `gh` 读取 PR head、diff、评论和未解决 threads，核对当前仓库、分支与最新 Issue 规格；保留本地无关改动，远程新增提交先安全同步。
2. 核对代码与失败场景，简述可执行 findings 的影响、建议和证据；不以评论自述代替事实。任务内真问题直接修复，无证据、存量、范围外、误报或过度设计建议按流程分拣。
3. 修复并完成受影响的定向验证；只有修复超出已确认规格、改变已确认的公共契约或扩大授权范围时才询问，不为恢复原定 API / 数据 / 权限 / 交互的行为重复确认。
4. 验证后暂存本轮修复，**commit 前**按工具适配执行必要 Review、修复与复查；通过后 commit、凭据预检、push 原 PR。纯回复或 docs-only 不启动独立代码 Review。
5. 请求包含回复 / resolve 评论时更新处理结论与真实验证结果，并 resolve 确实已处理的 threads；未处理项保留理由。重新读取 PR，报告 commit、push、Draft / Ready 状态和剩余风险。

评论回复与 resolve 仅在用户明确要求这些动作或此前已有对应授权时执行，不因加载本 Skill 推导外部发送权限；否则只在会话汇报修复与未处理项。Review 修复不代表任务验收或合并；需要那些动作时按交付流程另核对已有授权。

PR head 不明、工作区不能隔离、规格冲突、认证失败或需改写历史时暂停。不要在 push 后用暂存区 Review 冒充对已提交修复的检查。
