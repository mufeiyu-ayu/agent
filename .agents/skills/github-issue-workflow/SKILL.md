# GitHub Issue 交付

先读 [仓库基线](../../../AGENTS.md)、[交付流程](../../../docs/workflow.md) 与当前工具适配文件。流程、Review、验收和授权只以这些文件为准，本入口不复制另一套规则。

- 「完成 Issue #N」：按交付流程完成实现到验收 PASS 后合并与收口；用户可缩小为不 commit、停在 PR、Draft 或人工验收。
- 「继续」：先核对实际分支、PR 与已完成证据，从停止点继续；保留先前尚未撤销的范围限制。
- 「提交 PR」「验收」「合并并清理」：只执行本次点名的动作；不因加载本 Skill 扩大授权。

读取最新 Issue 正文、相关看板行和必要相邻代码。已有完整规格不额外加载产品研究全家桶；会改变方向的冲突才回会话确认。正式代码任务保留无关改动，在独立分支工作。

按 Issue 目标、范围和 AC 实现，完成定向验证与 commit 前 Review，处理真实缺陷。PR 与验收以实际远程 head 为准；commit 前 Review 仍有阻断问题时保留本地成果，不进入 commit / PR；已有 PR 的任一 AC FAIL / 未验证停在 PR，不合并。全部 AC PASS 只代表验收通过，合并核实后才按流程标 Completed。

docs-task 只检查相关链接、结构与 diff；research 写入 `docs/research/**`，不自动改变任务状态；阶段收口须满足自己的完成条件。只有本次授权包含对应动作时才提交、推送、合并、清分支或修改状态。

结束时报告真实停止位置、验证 / AC 证据、PR / commit 链接与剩余问题；未执行动作不写成完成。缺少凭据、工作区不能安全隔离、规格方向冲突或需要未授权操作时保留本地成果并说明。
