# 产品方案整理

先判断用户要会话草稿、更新产品方案，还是建开发 Issue；已有决定直接使用，只询问无法从上下文确定且影响范围的信息。按 [交付流程](../../../docs/workflow.md) 区分产品与开发规格。

正式产品方案只有 Claude Docs《Agent 产品方案》一份，仓库不新增 PRD，也不由讨论推导写入授权。工具无法访问该文档时交付可复制草稿并说明未写入，不改用其他平台创建第二份。

按需要包含以下内容，不凑章节、条数或指标：

- 问题与用户：真实使用场景、当前困难和证据。
- 目标：用户完成后应得到什么，有必要时附测量方法；假设与未知数字明确标出。
- 范围与不做：本次行为、P0 / P1 / P2；不为 P2 提前设计架构，不在产品方案排开发顺序。
- 行为与完成标准：可核对的输入、操作和结果，包含相关失败路径；简短需求用清单，复杂交互才写用户场景。
- 决策与未决问题：取舍依据、真正影响开工的未知项；不列可直接查证的事实为用户待办。

用户要求建 Issue 时，目标、范围与验收先拍板，再按 workflow 的 Issue 模板写自足正文；产品链接只作背景。草稿完成就交付，已授权的正式更新核对写入结果后结束，不自动生成额外交付物或推进实现。
