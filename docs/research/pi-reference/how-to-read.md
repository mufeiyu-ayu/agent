# 给带读智能体的使用说明

## 这个目录为什么存在

用户仍在学习自己的 agent runtime。完成现有源码学习后，希望以 Pi 的架构、目录组织和处理风格为主要参照，逐步形成**云端使用的 Agent 产品**。本目录把一次全仓研究变成以后对话可检索的证据库，避免每个新会话重复调研、套用旧版 Pi 印象或直接照搬 CLI。

研究准备完成不代表用户已经学完，也不代表重构已获批准。本目录的 roadmap 是后续学习和方案讨论顺序；正式任务状态仍看 `docs/tasks/README.md`，已建的 #115 → #116 → #117 不由这里改动。

## 新会话读取顺序

1. 读本目录 `README.md` 的主题路由，确认用户这次想读哪个问题。
2. 读 `source-snapshot.md`，核实两个 checkout 的 HEAD。
3. 只读对应模块说明及其中的一条真实源码链；需要总体定位再开图。
4. 对照 `current-agent-mapping.md` 找到我们当前实现的位置。
5. 学完一个问题后再看 `roadmap.md` 的下一步，等待用户决定节奏。

不要把全目录一次塞进模型上下文。模块说明是导航和事实索引，原始代码是最终证据。`modules/*-coverage.md` 用来核实研究边界，不是第一课教材。

## 每次只走一个场景

可选场景：直接回答；一次工具调用；同轮多个工具；断流；用户 Abort；观察者断开；进程重启；工具结果未记录；压缩；切换分支；重新附着；插件换代。

一段带读按下面顺序输出：

```text
本段问题 → 文件/符号 → 短代码 → 输入/输出/控制权
→ 成功与失败分支 → 谁拥有状态 → 对照我们 → 下一断点
```

- 区分模型请求、Provider 流事件、内存 reducer、durable entry、UI projection、transport frame。
- 对 `stream()`、async generator、事件订阅，查清实际何时发请求；不要套用“首次 next 才启动”的通则。
- `replay` 要说明重放什么：还原视图、还原模型上下文、继续 operation、重新执行外部副作用是不同能力。
- 取消要说明取消谁：HTTP/RPC 等待者、订阅、lane operation、模型请求、工具进程。
- 图只用于定位，节点不能替代函数证据。图中标为“候选”的内容不能说成当前实现。
- 纯观测字段才可说“不影响模型输入或控制流”；先查其消费者，不能仅凭 `event` / `trace` 命名判断。

## 提出重构前

给出当前具体问题、Pi 的实际做法、我们保留的不变量、最小改动范围和可验证失败场景。目录更整齐不是单独的重构理由；NestJS DI 已解决的组合问题不另写一套 Chord；现有 NDJSON 能满足的场景不自动换成 CBOR。

用户决定实现范围后才进入仓库正式流程。学习记录不更新正式 Completed 状态，不自动 commit、push、建 Issue 或替用户宣布学完。
