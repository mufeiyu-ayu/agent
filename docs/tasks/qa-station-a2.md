## 目标

在 A-1 数据基座上交付质检站核心工作台：译文对照详情页 + 四类动作的「接口真、实现假（或最小真）」版本，把阶段 C/D agent 环节所需契约与界面预先钉死。

## 范围与事实

- Prisma 增量：`TranslationTask`（status enum，A-2 恒为 PENDING）；`TranslationScore` 增补 lengthRatio / reviewNote / reviewedAt。
- admin-qa 新增六接口：文章详情（正文经 Cheerio 标签白名单净化并移除全部属性后下发）、译文详情、打分（最小真规则：长度比三档，ponytail 注释标注 naive 上限）、审核（先打分后审核，打回可附理由）、翻译任务（同语种 PENDING 幂等）、诊断（占位应答，标注 mock，不持久化）。
- contracts 新增 A-2 类型组；共享 `requestAdminRun` 增加 POST 能力。
- admin 详情页 `/qa/articles/:articleId`：首屏以质量结论、真实指标、判分过程和审核动作作为主工作区；整篇双栏降为按需展开的核查工具；保留语种切换、打回理由与诊断面板；列表页标题变为详情入口。
- 不碰 agent-runtime / llm / seo。

### A-2b 信息架构重构（2026-08-29，用户授权免 Issue 在本分支开发）

- 第三轮验收反馈定案「档案与操作分离」：文章模块只看状态，动作全部迁往独立工作台。
- 新增侧栏菜单「质检工作台」`/qa/workbench`（C 端风格）：左侧文章队列（搜索 / 仅质检集）选一篇文章；语种 chips（含缺失语种虚线 chip）；打分 / 通过 / 打回 / 重译动作；Agent 翻译流程演示面板——读取原文 → 术语库对照 → 翻译 → 自检 → 提交任务的五步时间线，仅最后一步真实写入任务队列，界面明确标注演示流、阶段 C 接入真实 Run。
- 文章详情页改为只读档案：语种矩阵（每语种规则分 / 结论 / 审核状态 / 排队标记）、译文预览按需展开、审核理由与时间、沟通记录只读展示，入口按钮跳转工作台。
- 诊断对话落库：新增 `QaDiagnoseMessage` 表（按文章时间线，问答成对写入、时间戳错开 1ms 保序）；POST diagnose 持久化问答并新增 GET 历史接口；应答仍为占位实现，阶段 D 只替换应答来源。
- `QaTranslationSummary` 增补 `ruleScore` 供档案矩阵展示。

## 边界记录

- 长度比为全局 naive 带（0.7–3.0 PASS / 0.4–4.5 REVIEW / 其余 REJECT），不区分语言族；A-3 按语言族校准。
- 正文视为不可信输入：前端只渲染服务端白名单净化后的结构化预览 HTML；脚本、表单、媒体、未知标签和全部属性均不会下发。
- 首版纯文本页面在用户验收时被确认难以阅读；2026-08-29 按最新反馈改为上述安全结构化预览，保留标题、段落、列表、表格与强调层级。
- 第二轮 UI 反馈确认后台关注点是翻译分析与决策，而非文章预览；同日将页面重排为分析优先，全文对照只在核查具体问题时展开。A-3 才接入的多维图表与问题清单不在 A-2 伪造占位数据。
- 第三轮反馈定案「档案与操作分离」（A-2b）：文章详情只读、动作集中在质检工作台；工作台 Agent 流程为前端定时步进的演示流，仅最后一步真实入队，不伪造真实翻译产出。
