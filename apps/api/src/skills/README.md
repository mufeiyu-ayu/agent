# Skills

`SkillsService` 管理本人技能的草稿/当前发布指针，`SkillsController` 只开放本人列表、预览、启停、删除和用户确认发布。模型工具在 `tools/skill-tools.ts`，没有发布工具。

- 未发布技能反复覆盖同一个 `SkillContent` 和 OSS 对象，首次发布只移动指针。发布后复用一个待确认草稿槽，确认时覆盖原发布对象；编辑次数不会增加内容记录或文件，不保留历史版本。
- 同一技能的保存和发布通过事务锁串行执行，以文件内容指纹校验预览，旧预览 409，重复发布幂等。OSS 不属于数据库事务，提交失败不保证文件恢复旧内容；读取以校验后的实际文件为准。
- 列表仅返回已发布技能；草稿由来源对话的文件卡片打开。发布后脱离来源会话，删除会话保留个人已发布技能。
- 删除会话时同事务标记该会话的未发布内容；单独删除技能也标记对应对象。SkillsService 按确切 key 删除 OSS，成功才删除内容记录；失败每分钟及重启后重试。采用会话→技能的锁顺序，避免删除后迟到保存。内置包不可覆盖。
- 每次聊天生成授权目录，显式选择先读取，自动选择经 read_skill。已加载内容在当前 Run 内复用；尚未读取的资源可能取得后续发布内容。实际正文/参考文件作为工具结果持久化，首次及后续模型采样 input.skills 保存目录与原始指令。
- 沙箱资源只在 bash 前准备到 root 管理的 `/opt/kuro-skills/<fingerprint>/<name>`，不进入用户源码归档。读取文本不创建沙箱。

手动创建通过 `POST /skills` 在一次事务内保存并发布，复用技能包校验；来源会话为 null，不创建占位聊天或游离草稿。创建弹窗只允许直接发布；已有发布技能只显示保存修改。对话草稿可继续保存，编辑/发布复用原接口。

每次覆盖前独立登记 `uploadId`，上传与外层事务结束后按身份清除；取消回滚仍留下可回收的对象记录。上传未确认完成时不允许再次覆盖或回收；进程中断留下的非空 uploadId 保留待核查，不按年龄假定上传完成。
