# Skills

`SkillsService` 管理本人技能的草稿/当前发布指针，`SkillsController` 只开放本人列表、预览、启停、删除和用户确认发布。模型工具在 `tools/skill-tools.ts`，没有发布工具。

- 一个技能只维护当前草稿/发布指针。保存先上传新对象、再提交指针；发布只切换指针，替换后的旧内容直接进入清理，不保留历史版本或运行引用。正常已发布技能清理后只有当前一份对象。
- 同一技能的保存和发布通过事务锁串行执行，以指纹校验预览，旧预览 409，重复发布幂等。OSS 不属于数据库事务，上传成功但提交失败留下未绑定对象，不覆盖原内容；确认上传结束后可清理。列表、预览和发布读同一已提交内容，读取仍校验对象指纹。
- 列表仅返回已发布技能；草稿由来源对话的文件卡片或会话草稿入口打开；后者通过 `GET /skills?conversationId=...` 找回已提交但返回 COMMIT unknown 的草稿，不恢复全站草稿列表。发布后脱离来源会话，删除会话保留个人已发布技能。
- 删除会话时同事务标记该会话的未发布内容；单独删除技能也标记对应对象。SkillsService 按确切 key 删除 OSS，成功才删除内容记录；失败每分钟及重启后重试。采用会话→技能的锁顺序，避免删除后迟到保存。内置包不可覆盖。
- 每次聊天生成授权目录，显式选择先读取，自动选择经 read_skill。已加载包继续复用现有 Map；不额外保护旧问答尚未读取的内容，更新或删除后可能不可再读（2026-10-12 用户确认的简化范围）。实际正文/参考文件作为工具结果持久化，首次及后续模型采样 input.skills 保存目录与原始指令。
- 沙箱资源只在 bash 前准备到 root 管理的 `/opt/kuro-skills/<fingerprint>/<name>`，不进入用户源码归档。读取文本不创建沙箱。

手动创建通过 `POST /skills` 在一次事务内保存并发布，复用技能包校验；来源会话为 null，不创建占位聊天或游离草稿。创建弹窗只允许直接发布；已有发布技能只显示保存修改。对话草稿可继续保存，编辑/发布复用原接口。

每次上传前独立登记 `uploadId`。尚未发起、确认成功或明确拒绝可按身份收尾；连接超时/结果未知、进程中断则保留身份，阻止同技能再写入及该对象回收，不按年龄假定结束。管理员核查确切 skillId/contentId/uploadId、OSS 对象指纹和请求实际结束后才能清除该身份；不以“对象暂时不存在”推断没有迟到 PUT。COMMIT unknown 的 HTTP 响应使用现有错误结构，明确提示刷新核对，创建端禁止直接重试。
